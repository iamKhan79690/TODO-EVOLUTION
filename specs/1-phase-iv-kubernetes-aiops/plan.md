# Implementation Plan: Phase IV - Kubernetes AI-Assisted Deployment

**Branch**: `1-phase-iv-kubernetes-aiops` | **Date**: 2025-12-23 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/1-phase-iv-kubernetes-aiops/spec.md`

## Summary

Deploy the Todo Chatbot application on a local Kubernetes cluster using **AI-assisted DevOps tools** (Gordon for containerization, kubectl-ai for manifest generation, kagent for operations, Minikube for cluster, Helm for packaging). This implementation corrects previous deviations by mandating the use of AI-assisted tools throughout the deployment process, ensuring 100% compliance with the Phase IV constitutional requirements.

**Technical Approach:**
1. **Environment Setup**: Docker Desktop 4.53+ with Gordon, Minikube v1.37.0+, kubectl-ai, kagent, Helm CLI
2. **AI-Assisted Containerization**: Gordon generates all Dockerfiles with multi-stage builds, non-root users, health checks
3. **AI-Generated Manifests**: kubectl-ai generates Kubernetes deployments, services, and Helm charts
4. **AI-Assisted Operations**: kubectl-ai and kagent handle deployment, troubleshooting, scaling, and analysis

## Technical Context

**Language/Version**: Python 3.13 (Backend/MCP), Next.js 16+ (Frontend)
**Primary Dependencies**:
  - Frontend: Next.js 16+, React 19+, TypeScript, Tailwind CSS
  - Backend: FastAPI 0.115+, SQLModel 0.15, Uvicorn, asyncpg, structlog
  - MCP: FastAPI, Pydantic, asyncpg, structlog
  - Infrastructure: Minikube v1.37.0+, Helm v3.15.0+, kubectl-ai, kagent
**Storage**: PostgreSQL (Neon managed service for external database)
**Testing**: Kubernetes health probes (liveness/readiness), manual integration testing
**Target Platform**: Local Minikube cluster (single-node, 4 CPUs, 8GB RAM)
**Project Type**: Web application (Next.js frontend + FastAPI backend + MCP server)
**Performance Goals**:
  - Container build time: < 5 minutes per service
  - Deployment time: < 15 minutes for complete application
  - Pod startup time: < 60 seconds per pod
  - Health check response: < 200ms p95
**Constraints**:
  - MUST use Minikube (NOT kind, k3d, or other distributions)
  - MUST use Gordon for containerization (NOT manual Dockerfile authoring)
  - MUST use kubectl-ai for manifest generation (NOT manual YAML writing)
  - MUST use kagent for cluster analysis (NOT manual log analysis)
  - All containers must run as non-root user (UID 1000)
  - All pods must have resource limits and health probes
**Scale/Scope**: 3 containerized services (frontend, backend, MCP), 5 pods (2 frontend, 2 backend, 1 MCP), local single-node cluster

### Phase 2: AI-Generated Kubernetes Manifests (Day 2-3)

**Objective**: Use kubectl-ai to generate all Kubernetes deployments, services, and Helm chart.

**Tasks**:

#### 2.1 Generate Deployment Manifests with kubectl-ai

**Frontend Deployment**:
```bash
kubectl-ai "Create a Kubernetes deployment for Next.js frontend with 2 replicas, LoadBalancer service on port 80, target port 3000, liveness probe GET /api/health with initialDelaySeconds=30, periodSeconds=10, readiness probe GET /api/ready, resource limits 500m CPU, 512Mi memory, requests 100m CPU, 128Mi memory, non-root user UID 1000, security context with readOnlyRootFilesystem=true." > kubernetes/frontend-deployment.yaml
```

**Backend Deployment**:
```bash
kubectl-ai "Create a Kubernetes deployment for FastAPI backend with 2 replicas, ClusterIP service on port 8000, liveness probe GET /health/ with initialDelaySeconds=15, readiness probe GET /health/, resource limits 500m CPU, 512Mi memory, requests 100m CPU, 128Mi memory, non-root user UID 1000, environment variables for DATABASE_URL, JWT_SECRET, OPENAI_API_KEY from Kubernetes secret named 'todo-secrets', security context with drop ALL capabilities." > kubernetes/backend-deployment.yaml
```

**MCP Server Deployment**:
```bash
kubectl-ai "Create a Kubernetes deployment for MCP server with 1 replica, ClusterIP service on port 8001, liveness probe GET /health/ with initialDelaySeconds=15, readiness probe GET /health/, resource limits 500m CPU, 512Mi memory, requests 100m CPU, 128Mi memory, non-root user UID 1000, environment variables for BACKEND_URL and OPENAI_API_KEY from secret 'todo-secrets', security context with allowPrivilegeEscalation=false." > kubernetes/mcp-deployment.yaml
```

**Validation**:
```bash
kubectl apply --dry-run=client -f kubernetes/frontend-deployment.yaml
kubectl apply --dry-run=client -f kubernetes/backend-deployment.yaml
kubectl apply --dry-run=client -f kubernetes/mcp-deployment.yaml
```

### Phase 3: AI-Assisted Deployment (Day 3-4)

**Objective**: Deploy the application to Minikube using kubectl-ai and monitor with kagent.

```bash

  --from-literal=DATABASE_URL="postgresql+asyncpg://todo_user:todo123@your-postgres-host:5432/todo" \
  --from-literal=JWT_SECRET="your-jwt-secret-here" \
  --from-literal=OPENAI_API_KEY="your-openai-api-key"
```

#### 3.2 Deploy PostgreSQL using kubectl-ai

```bash
kubectl-ai "Deploy PostgreSQL 15 using Helm with database name 'todo', user 'todo_user', password 'todo123', service port 5432, persistent volume 1Gi. Create the DATABASE_URL connection string and add it to the todo-secrets Kubernetes secret."
```

#### 3.3 Deploy Application with kubectl-ai

```bash
kubectl-ai "Deploy the todo-evolution Helm chart from ./helm-chart/ with release name 'todo-evolution' and namespace 'default'. Monitor the deployment and wait for all pods to be ready. If any pods fail, diagnose using logs and events, then provide remediation steps."
```

**Monitor Deployment**:
```bash
kubectl get pods -w
kubectl get services
```

#### 3.4 Troubleshooting with kubectl-ai

```bash
kubectl-ai "Verify service endpoints and troubleshoot connectivity issues between frontend and backend. Check service selectors, pod labels, and network policies."
```

#### 3.5 Access Frontend

Get Minikube service URL:
```bash
minikube service todo-evolution-frontend --url
```

## Risk Analysis and Mitigation

### Risk 1: Gordon Unavailable in User's Region
**Probability**: Medium
**Impact**: High (blocks containerization)

**Mitigation**:
- Primary: Use Gordon as specified
- Fallback: Use Claude Code to generate Dockerfiles with explicit documentation
- ADR: Create ADR documenting unavailability if fallback is used
- Documentation: Record deviation in completion report with timestamp

### Risk 2: kubectl-ai API Rate Limits
**Probability**: Medium
**Impact**: Medium (slows manifest generation)

**Mitigation**:
- Cache all generated manifests in git immediately
- Use natural language efficiently (batch related requests)
- Fallback: Use kubectl-ai for initial generation, manual edits for minor updates
- Documentation: Record all AI-generated YAML for replayability

### Risk 3: Minikube Resource Constraints on WSL2
**Probability**: Medium
**Impact**: Medium (limits deployment scale)

**Mitigation**:
- Validate system requirements before starting (4 CPUs, 8GB RAM)
- Start with minimum viable resources, scale up if needed
- Monitor resource usage with `kubectl top pods`
- Alternative: Document kind only with explicit deviation approval

### Risk 4: AI Tool Accuracy Issues
**Probability**: Medium
**Impact**: Medium (incorrect manifests causing failures)

**Mitigation**:
- Always validate AI-generated YAML before applying (`kubectl apply --dry-run=client`)
- Test in isolated environment first
- Manual review of security configurations
- Use constitution-enforcer skill to validate compliance

### Risk 5: Database Connection Failures
**Probability**: Low
**Impact**: High (application cannot function)

**Mitigation**:
- Verify external PostgreSQL connection string before deployment
- Test connectivity from pod to database
- Use kubectl-ai for troubleshooting connection issues
- Document database configuration in values.yaml
